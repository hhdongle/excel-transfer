# Excel Transfer

GitHub Pages에서 실행하는 계좌정보 관리와 주일경상비 이체파일 생성 사이트입니다.

## 사용하기

- `accounts.html`: 담당자 이메일/비밀번호 로그인 후 기준 계좌 자동 조회. 추가·수정·삭제는 Firestore 자동 저장. 열별 정렬, JSON 가져오기/백업 지원.
- `transfer.html`: 같은 브라우저의 로그인 상태를 재사용하고 계좌 원본 자동 조회. 부분 문자열 검색, 선택 팝업, 추가 토스트, 금액·합계, JSON과 엑셀 내보내기 지원.
- `sheets.html`: 좌우 독립 시트. Excel TSV 붙여넣기, 드래그/Shift+방향키 범위 선택, Ctrl+C 또는 복사 버튼으로 Excel과 상호 복사. 더블클릭/F2 편집, Enter/Tab 이동, Esc 편집 취소, Delete 내용 삭제, Ctrl+A 전체 선택. 기본 50행·12열이며 붙여넣을 때 자동 확장합니다(최대 2,000행·100열·전체 40,000셀). 셀 안 줄바꿈·따옴표·빈 셀을 보존하며 수식 계산과 서식은 지원하지 않습니다. 브라우저 메모리에서만 동작하고 서버 저장 없이 페이지를 떠나면 초기화됩니다.
- 이체 작업은 일요일 날짜를 골라 **주일별 저장**해야 합니다. 과거 기록 선택 후 **선택한 주일 불러오기**로 복원합니다. 초안의 미입력 금액도 저장할 수 있지만 엑셀 생성은 전 행 1원 이상이어야 합니다.
- 새 주일은 **새 주일 작업**으로 시작합니다. 이미 저장된 날짜를 수정하려면 그 기록을 먼저 불러옵니다. 다른 창에서 변경한 버전은 덮어쓰지 않습니다.

## 기존 JSON 이전

두 시트 작업의 Ctrl+Z(실행 취소), Ctrl+Y/Ctrl+Shift+Z(다시 실행)는 시트별 최근 100개 작업을 보관합니다. 셀 편집 확정, 범위 삭제, 여러 셀 붙여넣기, 행·열 확장을 작업 단위로 복원합니다. 실행 취소 후 새로 수정하면 다시 실행 이력은 초기화됩니다. 셀 편집 중에는 브라우저의 텍스트 실행 취소를 사용하며, 새로고침하면 작업 이력도 사라집니다.

1. 기존 계좌정보 JSON을 PC에 백업합니다. 기존 Drive를 사용했다면 이전 화면에서 JSON 다운로드한 파일을 준비합니다.
2. 계좌정보 화면에서 담당자 계정으로 로그인합니다.
3. JSON 불러오기로 기존 파일을 선택합니다. 아직 서버 자료는 바뀌지 않습니다.
4. 건수와 내용을 확인한 뒤 Firestore에 저장을 누릅니다. 중복과 앞자리 0은 원문 그대로 보존합니다.
5. 새로고침 후 자동 조회된 건수와 내용을 확인합니다.
6. 기존 이체 JSON은 주일경상비의 JSON Import로 가져와 해당 일요일을 선택한 뒤 주일별 저장합니다.

## Firebase 설정

프로젝트 `excel-transfer-cd0fc`, 담당자 UID `BHImPcznlFZDcrchzxzZqi8oRJd2`를 사용합니다. 웹 앱 설정은 공개 식별자이며 비공개 서비스 계정 키를 사용하지 않습니다. Authentication에서 이메일/비밀번호와 담당자 계정이 활성화되어 있어야 합니다.

Firestore 콘솔의 Rules에 `firestore.rules` 전체를 게시할 수 있습니다. 이 규칙은 담당자에게 아래 두 경로만 허용하고, 문서 직접 삭제·다른 UID 접근·잘못된 버전을 차단합니다. 웹 앱의 계좌 삭제는 계좌 목록 갱신으로 처리합니다. 기존에 DB 전체를 해당 UID만 허용하는 규칙을 게시했다면 앱은 그 규칙으로도 동작하지만, 이 저장소의 경로 제한 규칙으로 좁히는 것을 권장합니다. 저장소 업로드만으로 Firebase Rules가 배포되지는 않습니다.

## 저장 구조

- `users/{uid}/accountBooks/main`: 기준 계좌 배열, 건수, 버전, 생성/수정 시각
- `users/{uid}/weeks/{YYYY-MM-DD}`: 해당 일요일의 계좌·메모·금액 스냅샷, 건수, 버전, 생성/수정 시각

각 주일 기록은 기준 계좌의 ID만 참조하지 않고 당시 필드를 복사해 저장하므로, 기준 계좌를 나중에 수정·삭제해도 과거 내용은 바뀌지 않습니다. Firestore 트랜잭션으로 버전을 검사하고 충돌 시 저장을 거절합니다. 현재는 담당자 한 명의 보관 공간이며 여러 담당자의 공유 DB로 자동 확장하지 않습니다.

기준 JSON: `bank`, `accountNumber`, `name`, `notes` 문자열 배열. 이체 JSON에는 `amount` 정수 또는 `null`이 추가됩니다. 순번은 화면 전용이며 JSON에 저장하지 않습니다. 자료는 목록당 최대 1,000건/750KB로 제한해 Firestore 문서 한도를 넘지 않게 합니다. 기준 계좌 약 250건, 주일별 약 20건 용도에 맞춘 구조입니다.

엑셀은 은행·계좌번호·이름·금액 네 열을 헤더 없이 출력합니다. 계좌번호는 텍스트, 금액은 숫자 및 `#,##0`, 검정 테두리와 오른쪽 금액 정렬을 사용합니다. 노란색 강조는 없습니다. 엑셀 생성은 xlsx-js-style 1.2.0을 사용하며 라이선스는 vendor 폴더에 있습니다.

## 로그인과 백업

동일 브라우저의 Firebase 로그인 상태를 유지합니다. 비밀번호는 앱에 저장하지 않습니다. 로그아웃하면 화면 자료를 지우며, Firestore 데이터는 남습니다. 네트워크/권한/저장 충돌 오류가 나면 입력 목록은 화면에 유지됩니다. 저장 성공 안내를 확인하고, 주기적으로 JSON과 엑셀을 별도 보관하세요. 브라우저 데이터 삭제나 세션 취소 후에는 다시 로그인해야 합니다.

## 개발 및 검증

- `npm ci`
- `npm test`: 파싱·정렬·금액·엑셀·날짜·스냅샷 검사
- `npm run test:cloud`: Java 17 이상이 설치된 환경에서 Auth/Firestore 로컬 에뮬레이터를 시작하고 보안·이전·CRUD·충돌·과거 복원 검사. `demo-excel-transfer`만 사용해 실서비스에 쓰지 않습니다.
- `firebase emulators:start --project demo-excel-transfer --only auth,firestore` 후 정적 서버에서 `http://127.0.0.1:8770/accounts.html?emulators=1`로 브라우저 QA할 수 있습니다. 에뮬레이터 전환은 localhost/127.0.0.1에서만 허용합니다. 배포 도메인의 쿼리 문자열로는 데모 모드가 켜지지 않습니다.

Firestore SDK는 공식 gstatic CDN의 12.6.0 고정 버전을 사용합니다. npm 의존성은 테스트 전용이며 GitHub Pages 실행에 npm 서버가 필요하지 않습니다.
